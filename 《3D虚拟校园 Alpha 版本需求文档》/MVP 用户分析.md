# MVP 用户分析

## 1. 产品定位

项目名称（暂定）：

基于大语言模型 Agent 的 3D 虚拟校园体验平台


产品定位：

面向高校新生的沉浸式校园探索应用。

用户通过虚拟角色进入3D校园世界，提前了解校园环境、探索校园设施，并通过AI NPC获取校园信息。


核心理念：

让新生在正式入学前，以游戏玩家的方式提前体验未来校园生活。

---

# 2. 目标用户

## 核心用户：即将入学的新生


### 用户身份

- 即将进入高校的大一新生
- 已收到录取通知但尚未正式入校的学生


---

## 用户痛点


### 1. 对校园环境陌生

新生在入学前通常：

- 不知道校园整体布局
- 不清楚教学楼、宿舍、食堂位置
- 无法形成校园空间认知


### 2. 对未来校园生活缺少真实感

传统方式：

- 查看学校官网图片
- 浏览宣传视频
- 查看二维地图


存在问题：

- 缺少沉浸感
- 无法主动探索
- 难以建立真实体验


### 3. 缺少提前社交机会

新生入学前：

- 不认识同专业同学
- 不知道未来舍友
- 缺少共同话题


### 4. 信息获取成本较高

新生常见问题：

- 宿舍在哪里？
- 报到流程是什么？
- 哪些地方值得去？
- 学校有哪些特色？

通常需要：

- 搜索官网
- 咨询学长
- 浏览群聊


---

# 3. 用户需求


新生希望：

## 了解校园

- 提前探索校园环境
- 熟悉主要建筑位置
- 了解校园生活区域


## 获得校园信息

- 查询学校相关问题
- 了解专业和学院信息
- 获取新生指导


## 感受校园中的其他新生

- 看到其他新生角色
- 查看其他新生信息
- 感受虚拟校园中“有人存在”


## 获得沉浸式体验

- 创建虚拟角色
- 在校园中自由探索
- 像游戏一样体验校园


---

# 4. MVP提供价值


通过3D虚拟校园：

用户可以：

- 创建自己的虚拟角色
- 漫步校园地图
- 查看校园建筑信息
- 与AI校园助手交流
- 认识其他新生
- 提交使用体验反馈

# 10. 架构设计原则

## 1. 前后端分离

保证独立开发和维护。


## 2. AI服务独立

利用Python AI生态，并便于后期替换模型。


## 3. 3D与业务解耦

Three.js负责视觉和场景交互，业务逻辑由Spring Boot负责。


## 4. MVP优先

优先保证3D探索和AI交互，社交、任务和游戏化能力后续扩展。


---

架构约束：

**Three.js不直接连接AI服务。**

调用链保持为：

```text
Three.js / Vue3
↓
Spring Boot
↓
FastAPI AI
```

# 2. 前端技术选型


## 2.1 Vue3


### 选择原因

Vue3 是目前主流的前端框架之一，具有：

- 生态完善
- 学习成本较低
- 组件化开发能力强
- 适合构建复杂交互应用


### 项目用途

负责：

- 用户界面
- 页面管理
- 状态管理
- 与后端接口通信


应用场景：

- 登录页面
- 用户信息页面
- NPC聊天窗口
- 建筑信息展示
- 游戏UI界面


---

## 2.2 TypeScript


### 选择原因

相比JavaScript，TypeScript提供：

- 静态类型检查
- 更好的代码提示
- 更强的工程维护能力


### 项目用途

用于：

- Three.js开发
- 前端业务逻辑
- 数据类型约束


---

## 2.3 Three.js


### 选择原因

Three.js 是基于 WebGL 的3D开发框架。


相比传统游戏引擎：

- 无需C/C++
- 可以直接运行在浏览器
- 易于与Web应用结合


非常适合：

- Web3D应用
- 数字孪生
- 虚拟空间


### 项目用途

负责：

- 3D校园场景渲染
- 建筑模型加载
- 玩家角色展示
- 摄像机控制
- 场景交互


---

## 2.4 GLTF / GLB


### 选择原因

GLTF是Web端常用3D模型格式。


优势：

- 文件体积小
- 加载速度快
- Three.js原生支持


### 项目用途

用于存储：

- 校园建筑模型
- 玩家角色模型
- NPC模型


---

# 3. 后端技术选型


## 3.1 Spring Boot


### 选择原因

Spring Boot 是成熟的Java后端开发框架。


优势：

负责：

- 用户管理

- 校园数据管理
- 虚拟角色管理
- 用户反馈

## 3.2 Spring Security


### 选择原因

用于实现安全认证。


项目用途：

- 用户登录
- 权限控制
- Token认证


---

## 3.3 MyBatis 


### 选择原因

项目用途：

实现：

# 4. 实时通信技术选型


## WebSocket


### Alpha阶段决策

WebSocket暂缓接入。

Alpha阶段不实现玩家位置同步、用户在线状态和实时聊天。其他新生角色及基础信息通过普通HTTP接口加载。


---

# 5. AI服务技术选型


## 5.1 FastAPI


### 选择原因

Python生态在AI领域优势明显。


FastAPI：

- 高性能
- 异步支持
- 与AI框架结合方便


### 项目用途

作为独立AI服务。


负责：

- NPC对话接口
- Agent调用
- RAG流程


---

## 5.2 LangGraph


### 选择原因

传统聊天机器人只能进行简单问答。


校园NPC需要：

- 状态管理
- 工具调用
- 多步骤推理


LangGraph适合构建复杂Agent工作流。


### 项目用途

实现：

AI学长Agent


流程：

用户问题

↓

意图判断

↓

知识检索

↓

生成回答


---

## 5.3 RAG技术


### 选择原因

通用大模型不了解学校内部信息。


通过RAG：

让AI结合校园知识库回答问题。


### 项目用途


知识来源：

- 新生手册
- 学校官网
- 学院资料


流程：

文档

↓

Embedding

↓

向量检索

↓

LLM生成回答


---

# 9. 技术选型原则


## 1. 优先工程稳定性

选择成熟框架，降低开发风险。


## 2. AI能力独立化

AI服务独立部署，方便后续替换模型。


## 3. Web优先

采用Web3D方案，降低开发门槛。


## 4. 支持持续扩展

架构支持未来增加：

- 更多NPC
- 更多校园区域
- 游戏化玩法

# 3. 用户相关表


# 3.1 用户表 users


## 功能

存储用户基础信息。


字段：

| 字段         | 类型      | 说明     |
| ------------ | --------- | -------- |
| id           | bigserial | 用户ID   |
| nickname     | varchar   | 昵称     |
| avatar_url   | varchar   | 头像     |
| major        | varchar   | 专业     |
| admission_year | integer | 入学年份 |
| interest     | jsonb     | 兴趣标签 |
| created_time | timestamp | 创建时间 |


示例：

```json
{
 "interest":[
    "编程",
    "游戏",
    "摄影"
 ]
}
```

# 3.2 虚拟角色表 avatars

## 功能

存储用户在3D世界中的角色。

字段：

| 字段         | 类型      | 说明     |
| ------------ | --------- | -------- |
| id           | bigserial | 角色ID   |
| user_id      | bigint    | 用户ID   |
| model_url    | varchar   | 角色模型 |
| position_x   | float     | X坐标    |
| position_y   | float     | Y坐标    |
| position_z   | float     | Z坐标    |
| rotation     | float     | 朝向     |
| created_time | timestamp | 创建时间 |

说明：

position字段对应Three.js中的角色位置。
